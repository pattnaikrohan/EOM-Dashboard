Purpose & BackgroundOperations staff need a fast, weekly way to identify shipment jobs that require billing attention — specifically jobs that are missing revenue, have a WIP balance outstanding, or are showing a negative profit. Currently this is done by manually scanning CargoWise exports in Excel, which is time-consuming and error-prone.The tool solves this by letting any staff member upload the weekly CargoWise export and immediately see a filtered, colour-coded dashboard with the problem jobs highlighted. It also generates a formatted, password-protected Excel report they can share with their team without exposing the raw data.There are two variants in production:BLL variant — for AAW Bulk Liquid Logistics; uses black + mint green branding; password: aawbll-HLA##4-2026AAW Group variant — for the wider group with multiple branch codes; uses navy + red branding; password: aaw2026Both share identical logic. The AAW Group version additionally auto-detects the branch code from the report header row.2. Technical ArchitectureThe entire application is a single HTML file. There is no backend, no API, no build pipeline, and no framework. The file is self-contained and works offline once the CDN libraries load on first use (or can be fully offline if the libraries are inlined).2.1  LibrariesLibrary / ToolPurposeHow to includexlsx-js-style v1.2.0Read .xlsx files from the browser; write styled .xlsx exportsCDN: cdn.jsdelivr.net/npm/xlsx-js-style@1.2.0/dist/xlsx.bundle.jsofficecrypto-tool v0.0.19AES-256 encrypt the exported .xlsx so it opens password-protected in ExcelBrowserify the npm package (see Section 4) and inline the output as a <script> tagGoogle Fonts — Inter + DM MonoUI typographyStandard Google Fonts CDN link in <head>No backend, no build tool, no frameworkThe entire app is one .html fileOpen in any modern browser — Chrome, Edge, Firefox, Safari2.2  Application StructureThe HTML file contains three logical screens inside one page, toggled with display:none / display:block:Upload screen — shown on load; contains drag-and-drop zone and file pickerLoading screen — shown while FileReader processes the uploaded file (typically < 1 second)Dashboard screen — shown once data is processed; contains all interactive elementsCSS custom properties (CSS variables) are used for the entire colour scheme, making it straightforward to re-brand by changing ~15 hex values in :root {}. Data Processing — Reading the Excel File3.1  File ReadingThe browser's FileReader API reads the uploaded .xlsx as an ArrayBuffer, which is passed to SheetJS:const wb  = XLSX.read(arrayBuffer, { type:'array', cellDates:true });const ws  = wb.Sheets['Shipment Profile'];const raw = XLSX.utils.sheet_to_json(ws, { header:1, raw:true, cellDates:true, dateNF:'dd-mmm-yy' });⚠  CRITICAL — raw:true is mandatory.The CargoWise export formats financial cells with #,##0.00 (e.g. 42,988.80). If raw:false is used, SheetJS formats numbers using the cell's own format before returning them, causing parseFloat("42,988.80") to stop at the comma and return 42 instead of 42988.80. Every financial figure would be silently wrong. Always use raw:true.3.2  Locating the Header RowThe Shipment Profile sheet has a variable-length report header block above the data (job filters, branch code, date range etc.). The code scans rows 0–24 dynamically to find the row containing exactly "Shipment ID":for (let i = 0; i < 25; i++) {  if (raw[i]?.some(c => String(c||"").trim() === "Shipment ID")) { headerRow = i; break; }}3.3  Locating the Branch CodeThe branch code (e.g. BLL, BNE1, ME1) appears in the report header block, in a cell containing the text "Job Branch:". The AAW Group variant scans the pre-header rows to find and display it:for (let i = 0; i < 15; i++) {  const cell = raw[i]?.find(c => String(c||"").toLowerCase().includes("job branch:"));  if (cell) { branchText = cell.split(/job branch:/i)[1].split(",").map(s=>s.trim()).join(", "); break; }}3.4  Column MappingColumn indices are resolved by partial string match (.includes()), not fixed positions. This makes the tool robust to minor CargoWise export variations:function ci(...candidates) {  for (const c of candidates) {    const idx = headers.findIndex(h => h && h.toLowerCase().includes(c.toLowerCase()));    if (idx !== -1) return idx;  }  return -1;}// Example: ci("Total Revenue") matches "Total Revenue (Recognised+Unrecognised)"Full column map:JS FieldExcel Column (matched via .includes())NotesidShipment IDString — used as row identifierdeptJob Depte.g. BEX, FEI, FII — drives Export/Import logicstatusJob StatusFiltered to WRK and INV only; CMP loaded separately if neededoperatorJob OperatorUsed for operator filter barconsignorConsignor CodeShipper — used as client key for Export jobsconsigneeConsignee CodeReceiver — used as client key for Import jobsoriginOrigindestDestinationetdOrigin ETDFormatted to DD-MMM-YY string via fmtDate() helperetaDestination ETAFormatted to DD-MMM-YY string via fmtDate() helperrevenueTotal Revenue (Recognised+Unrecognised)Raw float — MUST use raw:true when readingwipTotal WIP (Recognised+Unrecognised)Raw floataccrualTotal Accrual (Recognised+Unrecognised)Raw floatcostTotal Cost (Recognised+Unrecognised)Raw floatprofitJob ProfitRaw float — alert if < 0isExpDerived from depttrue if dept[1] === "E"; false if dept[1] === "I"3.5  Date HandlingWith cellDates:true and raw:true, SheetJS returns ETD/ETA as JavaScript Date objects. These are immediately formatted to DD-MMM-YY strings for display:const MONTHS = ["Jan","Feb","Mar","Apr","May","Jun","Jul","Aug","Sep","Oct","Nov","Dec"];function fmtDate(v) {  if (v instanceof Date) return v.getDate()+"-"+MONTHS[v.getMonth()]+"-"+String(v.getFullYear()).slice(2);  if (typeof v === "number") { /* handle Excel serial date */ }  return String(v);}For sorting, a separate parseDate() function converts the formatted strings back to Date objects to get Unix timestamps for comparison.4. Dashboard Features4.1  Billing Quick Check ChecklistA collapsible panel at the top of the dashboard displaying 11 billing checklist items as a static reference list (not interactive checkboxes — ops staff use it as a visual reminder while working). Items include:Correct department / entity on jobCosting sheet cross-checkedQuote cross-checked (rates & scope)All sell lines raisedAll known costs accruedJob profit looks reasonableFLA amount confirmedEFS amount confirmed (if applicable)Correct currency used per customerFixed FX rate checked (creditor & debtor aligned)Invoice descriptions clean and client-ready4.2  Summary CardsFive KPI cards displayed in a row, each with a coloured top border:↗ Export Jobs — count of all active export jobs (dept[1] === "E")↙ Import Jobs — count of all active import jobs (dept[1] === "I")⚠ No Revenue — jobs where revenue === 0◈ Has WIP — jobs where WIP !== 0↓ Negative Profit — jobs where profit < 0All five counters update instantly when the operator filter is applied.4.3  Operator Filter BarOne button per operator (dynamically generated from data). "All Operators" shows everything. Clicking any operator button filters all three alert sections simultaneously. The active button is highlighted with the brand accent colour.4.4  Alert SectionsThree collapsible sections, each containing an Export tab and an Import tab:Jobs with No Revenue — billing action requiredJobs with WIP — work in progress balance outstandingJobs with Negative Profit — requires reviewWithin each tab, clicking any column header sorts the table by that column. Default sort: Exports ordered by ETD ascending (oldest first), Imports ordered by ETA ascending.Columns shown in each table: Shipment ID, Direction (EXP/IMP pill), Dept, Status (WRK/INV badge), Consignor, Consignee, Origin, Destination, ETD, ETA, Revenue, WIP, Accrual, Cost, Profit.The Operator column is only shown in the "All Operators" view; it is hidden when filtered to a single operator to save space.4.5  Export to Excel ButtonGenerates a formatted, password-encrypted .xlsx workbook entirely in the browser. No server involved. Structure:One sheet per operator — sheet name = operator name (truncated to 31 chars)Each sheet: title row → subtitle → KPI strip → NO REVENUE section → WIP section → NEGATIVE PROFIT sectionEach section: section header banner → Export sub-table (ETD sorted) → Import sub-table (ETA sorted)Last sheet: Summary — operator breakdown table with colour-coded alert countsThe workbook is encrypted using AES-256 (OOXML Agile Encryption) via the officecrypto-tool library, inlined into the HTML as a browserified bundle. Excel and LibreOffice will both prompt for the password on open.5. Encryption — How to Inline officecrypto-toolThe officecrypto-tool npm package must be browserified and inlined into the HTML so it works without a build step at runtime. Steps to generate the bundle:npm install officecrypto-toolnpx browserify node_modules/officecrypto-tool/lib/index.js \  --standalone officeCrypto -o officecrypto.bundle.jsPaste the entire contents of officecrypto.bundle.js inside a <script> tag at the very top of the HTML, before any other scripts. It exposes window.officeCrypto.Encrypt the workbook buffer after XLSX.write():const wbout     = XLSX.write(wb, { bookType:"xlsx", type:"array" });const encrypted = window.officeCrypto.encrypt(  new Uint8Array(wbout), { password: EXPORT_PASSWORD });const blob = new Blob([encrypted], {  type: "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet"});⚠  Always check the library loaded before calling it:if (!window.officeCrypto || typeof window.officeCrypto.encrypt !== "function") {  throw new Error("Encryption library not loaded.");}7. Export/Import Classification LogicDirection (Export or Import) is derived from the Job Dept code. The second character determines direction:Dept[1] === "E"  →  Export   (e.g. BEX, FEI, FES, ME1E)Dept[1] === "I"  →  Import   (e.g. BIX, FII, FIS, BN1I)Anything else    →  defaults to Exportfunction isExport(dept) {  const d = (dept || "").toUpperCase();  if (d.length >= 2 && d[1] === "E") return true;  if (d.length >= 2 && d[1] === "I") return false;  return true;}This works across business units. For BLL: BEX = Export, BIX = Import. For AAW Group branches (ME1, BN1, SY1 etc.): the dept code always contains the direction letter in position [1].8. Key Gotchas & Rules for the Dev TeamThe following issues have been encountered and resolved in the existing implementation. Make sure the new build avoids them:raw:true is non-negotiable when reading with SheetJSraw:false formats numbers using the cell's own Excel format (e.g. #,##0.00) before returning themparseFloat("42,988.80") = 42 — every financial figure is silently wrongAlways use raw:true + cellDates:trueExcel only supports one AutoFilter per sheetSetting auto_filter.ref multiple times (once per section) means only the last one survivesSolution: either set one autofilter covering the entire used range, or omit autofilter and sort the data before writingBrace/scope hygiene when removing featuresRemoving a code block (e.g. a CMP section) must also remove its closing braceA missing } leaves a function unclosed — the entire script fails silently with "handleFile is not defined"Always count opening vs closing braces when modifying JSopenpyxl colour hex values require the FF alpha prefix"111111" is treated as fully transparent — use "FF111111"This affects PatternFill, Font colour, and Side colour in openpyxlparseFloat on comma-formatted strings returns only the integer partparseFloat("1,234.56") === 1, not 1234.56Fixed by raw:true — but if raw:false is ever used, strip commas before parsingSheetJS merged cells need all covered cells to exist in the ws objectIf a merged range covers cells that were never written, Excel may show warningsSolution: fill empty cells with "" before applying mergesCSS custom properties vs inline base64 logosLogos embedded as data URIs make the file large but fully self-contained and offline-capableResize images before base64 encoding — a 1479×260 JPEG becomes ~740KB base64; resized to 600px wide it drops to ~62KB10.
